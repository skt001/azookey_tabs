# ロングプレス候補 — 設計基準

## 位置付け

この資料は、azooKey 向け QWERTY レイアウトでロングプレス候補を設計する際の考え方をまとめたものです。

ここで扱う候補は**設計上の候補**であり、すべてが `examples/` 以下の JSON に実装済みであることを意味しません。

## 共通方針

- 候補は原則として Unicode 上で単独のコードポイントを持つものを基準とする。
- 結合文字の任意の組み合わせを候補生成の単位にしない。
- 不可視文字・制御文字・ゼロ幅文字は対象外とする。
- 候補の採否基準と候補の並び順は分離する。
- 並び順は原則 Unicode コードポイント順とする。
- 実機のロングプレス実装は参考情報として扱い、候補集合の母集団にはしない。
- 調査段階では候補を広めに収集し、実用性・重複・用途を確認して整理する。

## en_qwerty

- 基本キーは A–Z。
- Unicode CLDR の Exemplar Characters を情報源の一つとして利用する。
- Unicode の分解、大文字小文字対応、文字名・注記、正書法上の関係などから対応を判断する。
- 単に音が似ているという理由だけでは割り当てない。
- 句読法、引用符、ハイフン・ダッシュ・マイナス、通貨記号などは文字候補とは別カテゴリとして扱う。
- 大文字化では Unicode の言語依存マッピングも考慮する。

## jp_qwerty

- 半角・全角の対応文字を直接入力候補として扱う。
- 特殊かな、小書きかななど、ローマ字入力から連想しやすい候補を扱う。
- 数字では全角数字に加えて漢数字・大字などを候補にできる。
- 句読点は `.` / `,` と `。` / `、` の相互関係を考慮する。
- 通常の IME 変換で入力することが自然なものは直接入力候補から除外する。

## 設計資料と実装例の区別

設計資料は「何を候補にできるか」を考えるためのものです。

JSON は「その設計を実際の azooKey 用レイアウトとしてどう表現するか」を試すためのものです。

したがって、両者の差分は必ずしも不整合ではありません。
